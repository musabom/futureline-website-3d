Objective
Full security audit remediation for FutureLine. Fix every confirmed vulnerability found across authentication, rate limiting, input validation, error handling, and data exposure — in priority order.

Findings Summary
🔴 CRITICAL
C1 — JWT role is stale for up to 2 hours after an admin changes a user's role
The role is written into the JWT at login time only. The JWT callback never re-reads the DB. If an admin promotes or demotes a user, that user's old role remains valid in their token for the full 2-hour session lifetime. A demoted admin can continue making admin API calls. File: src/lib/auth.ts (jwt callback)

C2 — In-memory rate limiter is bypassed in multi-instance (autoscale) deployments
The rate limiter stores state in a per-process Map. Each Replit autoscale instance has its own independent map. Requests distributed across instances are not rate-limited collectively. Brute-force login and email-spam attacks bypass all rate limits in production. File: src/lib/rateLimit.ts

🟠 HIGH
H1 — Instructor lesson POST passes raw request body to Prisma with no schema validation
prisma.lesson.create({ data }) where data is the raw, unvalidated body. Any Prisma-valid field on the Lesson model can be injected (e.g. courseId override, orderIndex manipulation across courses). The lessonSchema validator exists but is not used here. File: src/app/api/instructor/lessons/route.ts (line 47)

H2 — Public AI recommendation endpoint has no rate limiting
POST /api/ai/recommend is fully public, unauthenticated, and hits the database on every request. No rate limit exists. Any actor can spam it causing significant database load and scraping all published course data without authentication. File: src/app/api/ai/recommend/route.ts

H3 — Raw Prisma error messages returned to the frontend
Multiple routes return error.message from caught exceptions directly in the JSON response. Prisma errors expose table names, field names, constraint names, and relation details — a roadmap for an attacker probing the schema. Files: src/app/api/admin/courses/[id]/route.ts, src/app/api/admin/users/[id]/route.ts, src/app/api/instructor/courses/[id]/route.ts, and others.

🟡 MEDIUM
M1 — No protection against admin deleting their own account or the last admin
DELETE /api/admin/users/[id] has no check preventing an admin from deleting themselves or the last remaining admin, which would lock out the entire admin panel permanently. File: src/app/api/admin/users/[id]/route.ts

M2 — Instructor course status update accepts any string for status
PATCH /api/instructor/courses/[id]/status passes status from the request body directly to Prisma without validating it against the allowed enum values (DRAFT, PUBLISHED, ARCHIVED). File: src/app/api/instructor/courses/[id]/status/route.ts

M3 — Instructor lesson update passes partially-cleaned body to Prisma
prisma.lesson.update({ data }) after only deleting courseId. All other arbitrary fields remain. The lessonSchema is not applied. File: src/app/api/instructor/lessons/[id]/route.ts

🟢 LOW
L1 — Login emails logged to console in production
auth.ts calls console.info and console.warn with the user's email on every login attempt — successful or not. These appear in production logs. File: src/lib/auth.ts

L2 — Security headers missing from redirect responses
The middleware applies security headers to NextResponse.next() only. Redirect responses (e.g., when redirecting non-admins away from /admin) are returned before the headers block and do not carry the security headers. File: src/middleware.ts

Tasks
T001: Fix stale JWT role — re-read role from DB on every token refresh (C1)
Blocked By: []
Details:
File: src/lib/auth.ts
In the jwt callback, when user is NOT present (i.e., token refresh, not fresh login), query the DB for the current user's role using token.id and update token.role.
This ensures a demotion or promotion takes effect within seconds rather than 2 hours.
Acceptance: Changing a user's role in the admin panel takes effect immediately on their next API call, without requiring them to log out.
T002: Replace in-memory rate limiter with database-backed rate limiting (C2)
Blocked By: []
Details:
The Replit Database (KV store) integration is already installed (javascript_database).
Rewrite src/lib/rateLimit.ts to use the Replit KV store instead of an in-process Map.
Each key gets a DB entry with count and expiry stored as JSON.
Acceptance: Rate limits are shared across all server instances; brute force is blocked even in autoscale deployments.

File: src/app/api/instructor/lessons/[id]/route.ts — apply partial lessonSchema in PUT
Return a 400 with the validation error if parsing fails; only pass parsed.data to Prisma.
Acceptance: Arbitrary extra fields are stripped; invalid data is rejected with a clear message.

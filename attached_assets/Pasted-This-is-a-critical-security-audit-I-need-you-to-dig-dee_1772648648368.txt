This is a critical security audit. I need you to dig deep into every single file in this project and find every possible security vulnerability. Be thorough, assume nothing is safe, and leave nothing unchecked. Someone could potentially access other users' data, bypass payments, or gain unauthorized admin access. This is serious.
1. AUTHENTICATION & AUTHORIZATION

Are ALL routes protected with authentication middleware?
Can a logged-out user access any page or API endpoint they shouldn't?
Can a customer access instructor or admin routes by simply changing the URL?
Can a customer call any admin API endpoint directly (e.g. POST /admin/users)?
Is JWT or session token being verified on EVERY protected route — or just some?
Can someone forge or tamper with their role in the token/session?
Is there any route that trusts the role sent from the frontend instead of reading it from the database?

2. PASSWORD & RESET SECURITY

Are passwords hashed with bcrypt (or equivalent)? Are any stored in plain text?
Is the password reset token truly random and cryptographically secure?
Does the reset token expire? What happens if it doesn't?
Can someone request infinite password reset emails (no rate limit)?
Can someone reuse a reset token after it's already been used?
Is the reset token stored as a hash in the database — or plain text?

3. PAYMENTS

Is payment status verified SERVER-SIDE only — or can the frontend send "payment successful" and the backend trusts it?
Can a user access paid content without actually paying?
Is the payment webhook endpoint protected and verified (e.g. checking Stripe/payment gateway signature)?
Can someone replay a payment webhook to unlock content multiple times?
Is there any endpoint that changes a user's payment status without proper verification?

4. INPUT VALIDATION & INJECTION

Is ALL user input validated and sanitized before touching the database?
Is the app vulnerable to NoSQL injection or SQL injection anywhere?
Can someone register with a script or malicious code as their name/email?
Are file uploads (if any) validated for type and size?
Is there any eval() or dynamic code execution using user input?

5. DATA EXPOSURE

Do any API responses return sensitive fields like passwords, tokens, or internal IDs?
Can a user query another user's personal data by changing an ID in the URL (e.g. /api/users/123 → /api/users/124)?
Are database error messages exposed to the frontend (leaking schema info)?
Is any sensitive data being logged to the console in production?
Are there any hardcoded API keys, secrets, or passwords anywhere in the code?

6. RATE LIMITING & BRUTE FORCE

Is there rate limiting on the login endpoint? Can someone try unlimited passwords?
Is there rate limiting on the register endpoint? Can someone create thousands of fake accounts?
Is there rate limiting on the forgot-password endpoint? Can someone spam emails?
Is there any CAPTCHA or bot protection anywhere it's needed?

7. SESSION & TOKEN SECURITY

What is the JWT secret — is it strong or is it something like "secret" or "123456"?
Do JWT tokens expire? What is the expiry time?
Are tokens stored safely on the frontend (httpOnly cookies vs localStorage)?
If using localStorage for tokens, is the app vulnerable to XSS stealing the token?
Is there a logout endpoint that properly invalidates the session/token?

8. CORS & API SECURITY

What is the CORS configuration — does it allow ALL origins (*)?
Can any random external website make API calls to your backend?
Are there any API endpoints with no authentication at all that should be protected?
Is HTTPS enforced — can the app be accessed over HTTP?

9. ADMIN PANEL

Is the admin panel completely inaccessible to non-admin users both on frontend AND backend?
Can someone become an admin by editing their profile or sending a crafted request?
Are all admin actions (delete user, change roles, view all data) protected server-side?
Is there an audit log of admin actions?

10. ENVIRONMENT & CONFIGURATION

Is the .env file excluded from version control (in .gitignore)?
Are any secrets, API keys, or database URLs hardcoded in any file?
Is the app running in production mode or development mode when deployed?
Are detailed error stack traces being sent to the frontend in production?
